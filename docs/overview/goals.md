# 设计目标

围绕“让用户把项目交给 Agent，Agent 自主高质量地完成”这一核心诉求，第一阶段文档固化以下设计目标。它们同时也是后续实现阶段的验收锚点。

## 1. 委派质量自适应（推理强度）

Agent 拿到任务后，应**自行判断**该任务需要多少推理投入，并据此决定委派质量——而不是让用户手工选择每一档强度。

- 简单、机械的任务用低强度快速完成，控制成本与延迟；
- 复杂、高风险的任务自动升级到高强度，保证质量。

类比 CodeX 的 reasoning effort，但决策权在 Agent 自身的规划阶段。

## 2. 能力可特化

默认能力无法覆盖所有代码库与团队习惯。因此需要通过**能力特化层**对外开放接口，让用户**自行决定特化 Agent 的哪些能力**，例如：

- 缓存与复用特定项目上下文；
- 注入团队规范、私有工具与领域知识；
- 针对特定语言 / 框架调整 Agent 的行为。

特化应当**可插拔、可组合**，且不侵入核心编排逻辑。

## 3. 树形委派

委派任务应是一张**树形图**：根 Agent 拆解目标 → 子 Agent 承接 → 可继续向下委派。树形结构带来：

- 上下文隔离：每个子 Agent 只关注自己的子树；
- 可观测：任务进度与依赖关系可沿树追踪；
- 可恢复：子树失败可局部重试，不必整体重来。

## 4. 全平台分发

最终形态是**跨 macOS / Windows / Linux 的桌面应用**，交付给终端用户，而非仅面向开发者的 CLI 或云端服务。桌面壳的技术选型在后续阶段敲定。

## 非目标（第一阶段）

- 不实现应用代码，只交付文档站；
- 不追求与 CodeX 功能逐项对齐；
- 不预先锁定桌面壳框架（Tauri / Electron 待定）。
