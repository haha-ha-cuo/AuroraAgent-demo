# 对话运行画布与调用轨迹

这项设计已在 AuroraHarness 的 2026-11-07 开发工作树实现，尚未发布新的桌面安装包。本文描述该实现，不将本仓库旧 demo 的功能或路线图勾选等同于 AuroraHarness 的交付状态。

## 一个目标，两种视图

会话顶部以「对话 / 调用轨迹」切换。对话用轮次编号、左对齐的目标标题和 Aurora 回复签名呈现任务，减少重复执行明细；需要确认的操作保留在对应轮次中。每轮的「查看轨迹」进入对应运行，「回到对话」定位回原目标。

![AuroraHarness 对话运行画布，本地隔离工作区的实际界面](https://haha-ha-cuo.github.io/AuroraAgent-demo/images/conversation-canvas.png)

轨迹视图使用左侧轮次索引与右侧调用时间线，支持筛选全部、执行中和异常，搜索工具、参数和结果，展开查看输入、输出、错误、所属角色和耗时。角色阶段显示本轮冻结的 Agent 与模型名称，阶段输出和视觉审查证据仍可展开。

![AuroraHarness 调用轨迹，三个实际工具调用及展开结果](https://haha-ha-cuo.github.io/AuroraAgent-demo/images/call-trace.png)

手机将轮次索引改为横向条，详情在剩余区域内滚动。页签支持方向键、Home / End 与可见焦点；切换保留草稿和对话位置。轨迹中保留停止入口，有审批或其他待输入内容时提示返回对应轮次处理。

## 记录真实执行

轨迹来自工具实际执行，不根据任务派发事件编造开始时间或耗时：

| 运行状态 | 轨迹行为 |
| --- | --- |
| 等待或拒绝审批 | 工具未执行，不创建调用记录 |
| 工具开始与完成 | 独立调用 ID、结构化参数、文本结果、UTC 时间与单调时钟测得的耗时 |
| 进程非零退出、超时 | 调用记录失败及错误信息 |
| 用户取消 | 执行中的调用记录取消，已完成调用保留原终态 |
| 重试 | 新运行和新调用关联来源，旧历史不改写 |
| 运行时重启 | 遗留调用标记中断，无法得知的耗时显示未知 |
| 断线或读取失败 | 保留已加载记录，显示连接状态或错误，允许重新读取 |

累计工具耗时为每次已知耗时之和，并行时可能大于运行总时长。阶段条用于展示角色执行，不等同于逐次模型 HTTP 请求的网络追踪，也不提供模型内部思维过程。

## 实现位置与兼容边界

- Python：`orchestration/tool_tracing.py` 在确认门放行后包裹工具执行；迁移 `005_tool_calls.sql` 保存 `tool_calls`，关联运行、角色执行和任务键。记录随运行与会话级联删除。
- 协议：`run.get` 增加 `toolCalls`；`tool.started/completed/failed/cancelled/interrupted` 通过现有 stdio/WebSocket 通知通道发送，使用稳定的 `tool_call_id`。兼容现有 v1，旧快照可没有调用记录。
- 前端：`TracePanel` 负责展示，`traceStore` 按调用 ID 合并实时事件与快照。迟到的执行中快照不能覆盖终态，删除后迟到响应不能恢复已清除的缓存。
- 安全：结构化敏感字段与已登记供应商凭据在入库/推送前脱敏；参数与输出作为文本显示，不执行其中的 HTML。任意工具文本的完整凭据边界仍需独立验收。

AuroraHarness 当前仍存在 camelCase 与 snake_case 混用等契约差距；本页增量实现说明不会改写[协议目标](runtime-protocol.md)，也不会把递归委派、持久检查点、附件、真实 token 流与 eval 等剩余缺口标成完成。
