# 关键决策记录（ADR）

> 记录影响架构走向的关键决策、背景与待办。新增决策请沿用 ADR 编号并标注状态（已采纳 / 待定）。

## ADR-001：能力特化层与缓存解耦 {: #adr-001 }

- **状态**：已采纳
- **背景**：早期构想以 “KV Cache 层” 同时承载「能力特化」与「缓存」，但 “KV Cache” 在 LLM 语境中通常指推理时的注意力 key-value 缓存，容易混淆。
- **决策**：拆分为两个独立概念——**能力特化层**（用户可插拔的上下文、工具、提示、检索策略）与**缓存层**（prompt / 结果复用，纯内部优化）。
- **影响**：对外接口面向能力特化层；缓存作为独立优化模块单独设计。
- **文档**：[能力特化层](capability-layer.md)

## ADR-002：模型接入 = 远程 API + 本地 API 管理 {: #adr-002 }

- **状态**：已采纳
- **背景**：桌面本地化若走本地推理（Ollama / llama.cpp），打包体积、硬件适配、三平台维护成本高。
- **决策**：模型统一走**远程 API**，应用内提供**本地 API 管理层**负责密钥、端点与客户端构建；密钥不进入 Agent 上下文、不落日志；无密钥回退 **mock 模式**。
- **影响**：跨平台一致、可切换供应商；需妥善处理密钥安全。
- **文档**：[模型接入与本地 API 管理](model-access.md)

## ADR-003：直接用 langchain-core + langgraph {: #adr-003 }

- **状态**：已采纳
- **背景**：`langchain` 元包偏旧、体积大，现代组合是 `langchain-core`（核心抽象）+ `langgraph`（编排）+ 各集成包（如 `langchain-openai`）。
- **决策**：不引入 `langchain` 元包，直接依赖 `langchain-core`、`langgraph` 与所需的集成包。
- **影响**：更可控的依赖面与升级成本；文档与代码统一使用新拆分。

## ADR-004：委派树的失败传播与资源上限（待定） {: #adr-004 }

- **状态**：待定
- **背景**：树形委派需要明确失败语义与资源边界，否则会出现无限递归与成本失控。
- **待决策项**：
  - 叶子失败在哪个层级触发父节点重规划；
  - 子树局部重试的状态保存与次数上限；
  - 树深 / 扇出 / 总预算（token、成本、时长）上限；
  - 评审（review）节点的触发条件与通过标准。

## ADR-005：安全权限模型（阶段二一级设计项） {: #adr-005 }

- **状态**：已采纳（确认门已落地最小实现，其余待定）
- **背景**：能读文件、跑 shell、改代码的 Agent 本质是本机 RCE 入口，且用户代码库本身可能被提示注入。
- **已落地**：
  - 确认门（`demo_agent/gate.py`）：工具按风险分级 read / write / execute，写与执行默认拒绝，需确认才放行；`--yes` 全放行、交互终端逐条确认、非交互默认拒绝。
  - 敏感文件守卫：`list_files` / `read_file` / `write_file` 拒绝 `.env`、密钥文件。
- **待决策项**：
  - 命令执行工具的白名单与 dry-run；
  - 文件系统沙箱（seatbelt / 容器）；
  - MCP Server 的供应链与权限边界；
  - 注入上下文（能力特化层）的防提示注入策略。

## ADR-006：评估（eval）策略 {: #adr-006 }

- **状态**：已采纳（最小 eval 集已落地）
- **背景**：“自适应推理强度”需要一个基准来校准——没有 eval，无法判断高强度档位是否真的更优。
- **已落地**：
  - `demo_agent/eval.py`：12 个任务 fixture，在确定性 mock 模式下校验「任务识别 + 推理强度分档 + 端到端结果」；
  - 零 token 成本、可反复跑，并纳入 pytest 回归（`tests/test_eval.py`）；
  - `demo_agent/experiment.py`：judge 打分 + 三档对照实验，产出质量分 vs token 成本对比；
  - 推理强度真实影响 worker 行为（简答 / 完整 / 完整 + 自评改进，见 `EFFORT_CONFIGS`）；
  - 后续 LLM 规划器落地后，用同一套 fixture 对比校准。
- **待决策项**：
  - judge 的方差与偏差控制（多次采样 + 人工抽检）；
  - 更细的档位策略（不同模型 / temperature / max_tokens）。
