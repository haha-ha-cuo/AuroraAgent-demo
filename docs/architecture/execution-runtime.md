# 执行校验与资源限制

本页记录 AuroraHarness 开发工作树的实现与验证。面向使用者的操作步骤见[快速开始](../getting-started/demo.md)。

## 计划校验

`core/plan_validation.py` 在派发前验证整份计划：任务结构、唯一 ID、描述、强度、工具授权、参数 JSON Schema 和函数签名。后续任务无效时，前面的合法工具也不会执行。

- 普通空计划明确失败，只有保留完成工作的内部重试可使用空计划。
- 计划上限 1 MiB；整数 ID 转成字符串后检查冲突，布尔值与空值拒绝。
- 本地 schema 引用可用，外部引用不会在验证时访问网络。
- 自定义规划器与模型规划器使用相同校验；只读 plan 模式同样验证。
- MCP 工具名由闭包固定，模型参数不能覆盖调用目标。

拒绝原因通过 `EMPTY_PLAN`、`DUPLICATE_TASK_ID`、`TOOL_NOT_ALLOWED`、`INVALID_TOOL_ARGUMENTS` 等错误码返回，并保留失败运行。

## 受限递归

根角色深度为 0。子角色有独立模型、指令和工具权限，继承工作区、沙箱、审批策略与整轮预算。允许相互调用的角色可形成循环，深度上限负责终止；不会靠删除递归能力规避循环。

| 配置 | 默认 | SDK 范围 |
| --- | --- | --- |
| `max_depth` | 4 | 0–16，0 禁止进一步委派 |
| `max_plan_tasks` | 8 | 1–256 |
| `max_total_tasks` | 128 | 1–4096 |

通过 `AgentRuntime(execution_limits=ExecutionLimits(...))` 配置。每轮冻结配置，所有后代与视觉返修共用任务计数。澄清重规划替换同角色预留，审批恢复不重复计数；新运行及重试采用当时的配置。

深度超限在创建下一层模型前拒绝；总任务超限在新叶子执行前拒绝。局部任务键可以重复，持久 UUID 与父任务 ID 区分不同子树。审批逐层恢复，并关联最深层真正等待的角色和任务。

递归结果汇总提取子结果正文，避免逐层 JSON 转义。16 层执行已有行为测试；同一小任务曾因嵌套转义生成约 95 万字符的汇总，现已修复。

## 历史与事件

`task.created/started/waiting/completed/failed` 包含稳定任务 ID、父任务 ID 和完整展示字段。信封兼容 snake_case 与既有 camelCase 来源。前端允许开始早于创建、父节点迟到、重复终态和旧快照，按运行隔离，异常环在展示时断开。

工具轨迹保存在迁移 005 的 `tool_calls`，通过 `run.get.toolCalls` 与 `tool.*` 事件读取。审批等待不创建调用；执行时记录输入、输出、错误、UTC 起止和单调时钟耗时。重启遗留调用标记中断，未知耗时不补造。结构化敏感字段和已登记供应商凭据在保存及推送前脱敏。

## 重启后继续运行

开发版在等待审批、澄清、预览配置或审查决定时保存检查点。重启后，用户可以在同一轮运行中处理待办，已完成的工具调用保留在原任务下。运行时为待处理的审批换发公共 ID，沿用原截止时间，到期按超时处理。

恢复时会核对 Git 工作树、索引和分支，以及当前角色、模型、沙箱和审批权限。工作区或配置发生变化时，原运行转为中断。使用动态能力策略、进程内回调、MCP 扩展工具或 Git 分离索引的运行，目前只支持进程内继续。

如果运行时在工具执行期间退出，未结束的调用会标记为中断。重试前应先核对已产生的文件写入或外部操作。

## 验证与剩余工作

本轮新增 28 个计划校验场景、12 个递归场景、6 个前端任务事件场景及 1 个递归树浏览器场景。覆盖四层连续审批、最大 16 层、循环终止、共享预算、上下文隔离、取消真实进程，以及整轮/子树/叶子重试。

全量检查：Python 266 项通过、1 项浏览器预览受本机沙箱限制跳过；前端 71 项及类型检查通过；Chromium 14 个场景通过；统一 lint 通过。界面另核对了实际 PingFang SC 字形与手机布局。已有主题调整场景的 ResizeObserver 开发告警仍待修复。

仍需实现：设置页资源配置、整轮时长/token/成本预算、依赖调度、扩展工具的重启恢复、完整消息流事件与真实 token 流。当前没有发布新桌面安装包。
